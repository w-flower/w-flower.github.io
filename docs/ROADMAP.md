## 二、本次已落地的三个功能

### 1. 知识库页 `/kb/`（快速索引 + 知识点桥梁）
- **搜索**：标题/课程/标签/正文即时过滤（防抖 150ms）；
- **筛选**：按课程（工科数学分析 / C++ 程序设计 / 数据结构 / 文章标签）、按类型（笔记/文章/代码）；
- **关系图谱**：力导向图（纯 JS，无外部库）——
  - 节点 = 笔记/文章/代码，颜色按类型区分；
  - 边 = **同课程按章节顺序连成「学习路径链」**（而非全互联毛线团）+ 文章/代码间**共标签**连线；
  - 点节点 → 高亮它的上一节/下一节（相关笔记），下方卡片只留它和邻居；
- 支持 `?q=` 从起始页带搜索词进来。

### 2. 起始页 `/start/`（柠檬风）
- 中央大搜索（回车跳知识库带词）、圆角磁贴快速入口、实时时钟/日期、按时段问候；
- 融合方式：不是生硬替换首页，而是作为「书签主页」存在——首页保持封面叙事，起始页负责"打开浏览器第一屏"的场景。

### 3. 工数笔记导入完成
- 15 篇工科数学分析笔记已导入并打标签（course=工科数学分析）；
- KaTeX 公式全站渲染正常，含表格内公式（已修复 GFM 表格竖线冲突导致的裸 `$` 问题）。

## 三、未来可做：AI 语义桥梁（LLM Wiki 方向）

现在的桥梁靠「共标签/同课程/章节顺序」这类**结构信号**。下一步可以做**语义桥梁**：

1. 构建期把每篇笔记的前 500 字喂给 LLM，让它输出这篇讲了什么概念、与哪些篇目有前驱/后继关系，生成 `relations.json`；
2. 知识库页把 `relations.json` 的边叠加到图上（不同虚线样式区分"结构边"和"语义边"）；
3. 文章底部「相关笔记」优先取语义边。

这样桥梁就不是"都挂同一门课"的粗粒度关系，而是"这篇的夹逼定理会用到上一篇的确界定义"这种真理解关系。工作量集中在构建脚本 + 一次 LLM 批处理，前端不用大改。
