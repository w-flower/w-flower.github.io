# 动效丰富化 + Word 式编辑器 · 方案 v2

> 只写方案与实现方式，不写代码。
>
> **v2 改动**：① 工具栏优先级提到最高，并且明确"VS Code 里就行"——这条路零开发成本，今晚就能用；② 新增 Canva 式花哨元素与"文本逐个出现"；③ 新增性能预算表，把"雪花这类"明确列进黑名单。
>
> 两份需求有一条共同主线：**让"发表"这个动作变轻**。动效让站点活着，编辑器让写字变容易。分开做会互相抵消——编辑器再好，保存没反馈就不敢信；动效再炫，写字还得开 VS Code，一切白搭。

## 〇、一页版结论

| 需求 | 结论 |
|---|---|
| 工具栏 | **电脑端走 VS Code + Office Viewer 扩展**（Vditor 内核，所见即所得 + 完整工具栏 + 存回 .md）。今晚装完就能用，我不写一行代码 |
| 编辑器 | **md 是唯一真相源，编辑器按场景分开，不追求统一**。电脑认真写 → VS Code；手机随手记 → 网页 `/write`；发一句话 → 微信 |
| 动效 | 抄 B 站的**IP 化微交互**和 GitHub 的**信息反馈型动效**；花哨度抄 Canva 的**文字处理**（渐变、荧光笔、贴纸字） |
| 性能 | 一条铁律：**只用"一次性的、合成器友好的"动效**。连续的逐粒子循环（雪花、雨、粒子海）一律不做 |

## 一、工具栏与编辑器：先分场景，再选工具

### 1.1 先破除一个错觉：不需要"一个编辑器通吃"

过去我把编辑器当成"要做一个东西"，这是错的。正确拆法按**写作场景**分：

```
你在哪儿写？
├─ 电脑前，写长文、写代码笔记
│   └─ VS Code + Office Viewer 扩展     ← 工具栏 + 所见即所得，零开发
├─ 手机 / 平板，随手记两句
│   └─ 网页 /write 编辑台                ← Astro Actions 写 md，我来做
└─ 只想动动手指发一句话
    └─ 微信消息 → 我归类成文 → 提交      ← 复用已打通的 IM 通道
```

三条路**共用同一个 md 文件夹**，所以不需要统一编辑器，只需要统一存储。这是整个方案里最省事的一个判断。

### 1.2 电脑端：VS Code + Office Viewer（首选，今晚可用）

**扩展**：`cweijan.vscode-office`（Database Client 团队出品，114 万+下载，4.2.0，约 13 MB）

它做的事正好是你要的：把 VS Code 默认的 Markdown 编辑器**替换成 Vditor 的所见即所得编辑器**——

- **完整工具栏**：加粗、斜体、标题层级、列表、表格、代码块、引用、分割线、图片、链接，全部是按钮，不用记语法
- **直接编辑你的 .md 文件**，保存还是标准 md，git diff 照常工作，随时能用任何其他工具打开
- 粘贴图片自动转存；右键可导出 PDF / DOCX / HTML
- 快捷键一套（Ctrl+B 加粗这类照常）

**风险要知道**：Vditor 上游维护放缓（社区反馈），长时间不更新的可能性存在。备选是社区改进版 `rjwang` 的 Office Viewer Enhanced。真出问题就退回方案 1.3，损失为零。

**另一条零风险路**（不想换编辑器就用这个）：VS Code 自带 Markdown 预览 + `yzhang.markdown-all-in-one`（快捷键、自动目录、列表编辑）+ 分屏预览。缺点是"半所见即所得"——左边语法右边预览，不是真 WYSIWYG。

**结论**：电脑端**不开发任何东西**。装扩展，完事。这也解释了为什么前面说"编辑器第一条决策是 md 为唯一真相源"——正因为存储是 md，VS Code 才能零成本接管，否则你换编辑器就得先迁移数据。

### 1.3 手机端：`/write` 网页编辑台（我来做）

形态：站点里开一个 `/write` 路由，左边表单、右边实时预览，保存一按，md 落盘。

- **Astro 7 Actions** 在服务端把 frontmatter + 正文拼成字符串写进 `src/content/`，content layer 热更新，预览页立刻变
- 零账号、零 OAuth、零外部服务、零费用
- 表单字段直接复用现有 schema（title / course / status / tags / mood / tools / draft）——**schema 即表单**，不维护两套定义
- 工具栏照 1.2 的思路做：加粗、行内代码、代码块、表格、图片、分割线，一键插入 md 语法
- 图片拖进正文 → 存 `public/uploads/` → 自动插入 `![](...)`，解决现在插图靠手动放文件的痛点
- 保存成功接一个动效反馈（见第二章）

**Word 感从哪来**——这是关键，分两步：

第一步"**结构化 Word**"：标题、分类、标签、日期全是表单控件，不是敲 `---` 分隔线；正文区带工具栏；右侧实时预览复用文章页的 `.prose` 样式。做到这步，"像 Word 那样方便"已经成立 80%——因为 Word 用户 80% 的便利来自"不用记语法"，不是来自块级拖拽。

第二步"**真所见即所得**"：正文区换 Milkdown（无框架、能塞进 Astro 页面、md 进 md 出、MIT）。风险是核心维护者只有一人（bus factor = 1），所以是可选升级，不做也不影响第一步。

**明确不做**：Tiptap 自己搭（2–4 周调 UI，license 有变动史）、Editor.js（JSON 输出，违背 md 为真相源）、BlockNote（块节点树，md 语义保真不可靠）。

### 1.4 云端：git-based CMS（部署决策落地后再做）

| 候选 | 许可证 | 要账号吗 | 判断 |
|---|---|---|---|
| **Keystatic** | MIT | 本地模式不要 | **首选**。schema 驱动表单，本地模式零配置可用，Astro 内容集合原生支持 |
| Sveltia CMS | MIT | 要 GitHub OAuth | 备选。Decap 的现代替代，纯静态无后端 |
| Pages CMS | 开源 | 要 GitHub | 更轻但定制弱 |
| EmDash | MIT | 要数据库/Workers | 太重。Cloudflare 出品、2026 年 9 月才 1.0，个人博客用不上 |
| TinaCMS | 免费档 | 要 Tina Cloud 才能生产用 | 免费档限制多，不如 Keystatic |

Keystatic 的额外好处：它的本地模式**就是 1.3 的另一种实现**，表单结构、字段定义、md 落盘逻辑全都能继承，将来到云端几乎无痛。

### 1.5 微信一句话上传（放到最后）

复用本机已打通的 IM 通道（微信 ClawBot / QQ 机器人）。你发一句"记一下：vector 扩容 1.5 倍是为了复用内存，工具 MSVC"，我这边：判断类型 → 补 frontmatter → 写 md → 构建 → push → 上线。

**建议写够 20 篇再做**。理由：没有固定域名时，做出来只是换个方式更新一个打不开的地址；而且你的分类习惯还没稳定（micro 的 mood、tools 字段都是最近才加的），AI 归类规则现在定等于凭空猜。

## 二、动效：抄谁的，抄什么，花哨到什么程度

### 2.1 三个来源，三种不同的东西

**B 站 —— 学"把 IP 做进交互"**

B 站强的不是动画多，是**品牌形象会参与交互**。进度条上那个小电视，拖拽时眼睛左右跟着动；长按点赞一圈走完，点赞投币收藏三个一起亮。合起来你会觉得"这个站是活的，而且它认识我"。

| B 站原版 | 你的版本 | 数据来源 |
|---|---|---|
| 进度条小电视眼睛跟随方向 | 阅读进度条上放罗小黑，滚动时脸朝上/朝下，滚得快变"加速模式" | 已有 `.progress` + `public/avatar.jpg` |
| 长按一键三连 | 文章底部长按 0.8 秒：点赞 / 收藏 / 复制链接一起完成，附随机感谢语 | 三件事都能本地实现 |
| 点赞心形迸发 | 点赞按钮点击迸发 6–10 个粒子，轻微物理散开 | 纯 CSS / WAAPI |
| 弹幕 | 随笔页做成弹幕墙：每条 micro 从右往左飘，可暂停 | micro 就是 1–3 句话，天生适合 |
| UP 主自定义感谢语 | 连点站名 5 次的彩蛋升级成一小段罗小黑动画 | 已有 secret 彩蛋的架子 |

**进度条罗小黑和弹幕墙最值得做**——用的是你独一无二的素材（头像 + 半夜写的短句子），模板站抄不走。

**GitHub —— 学"信息密度型反馈"**

| GitHub 原版 | 你的版本 | 回答什么问题 |
|---|---|---|
| 贡献热力图 | **写作热力图**：一年 365 格，颜色深浅按当天写没写 | "我是不是又鸽了" |
| ⌘K 命令面板 | 搜索升级为命令面板：⌘K 唤起，键盘上下选，直跳文章 | "我想找的那篇叫什么" |
| Hovercard | 已有（列表页悬停浮卡） | "这篇讲什么，要不要点进去" |
| Star 爆开 | 文章底部"收藏这篇"，存 localStorage，图标弹一下 | "我刚看到哪篇了" |

热力图特别推荐：数据全现成（content 里每篇的 `date`），实现是一张静态 SVG 零 JS，而且是**唯一能让访客一眼看懂"这个人在持续写"的组件**，比任何自我介绍都有说服力。

**Canva —— 学"文字可以当成设计材料"**

Canva 的核心不是动画，是**把文字当图形处理**。这些全部是 CSS 就能做到的，零 JS：

| Canva 手法 | 落地位置 | 成本 |
|---|---|---|
| **荧光笔高亮**（文字下半截刷一道半透明色） | 正文重点句、摘要 | 一个 `linear-gradient` |
| **渐变文字** | 首页大标题 DHua、章节标题 | `background-clip: text` |
| **贴纸字 / 描边字** | 标签、彩蛋文案 | `-webkit-text-stroke` + 多层 text-shadow |
| **文字坐在色块上** | 标签栏第一个"标签"胶囊、引句 | 一个圆角矩形 |
| **首字下沉** | 长文第一段 | `::first-letter` |
| **拍立得相框** | 文章里插图、头像 | 白边 + 轻微旋转 + 阴影 |
| **装饰性引号 / 花纹** | 引句、blockquote | 静态 SVG |
| **大字横带滚动** | 页面分隔带 | CSS transform 循环 |

**文本逐个出现**（你单独点名的）：拆成 span + `animation-delay: calc(var(--i) * 30ms)`，动画只碰 `opacity`/`transform`，合成器跑，不占主线程。三条使用纪律：

1. **只用于标题、引句、首屏文案**，正文永远不逐字出现——正文是要读的，不是用来看的
2. **按词拆，不按字拆**。一段 200 字按字拆是 200 个节点，按词拆是 120 个左右且视觉上几乎无差别
3. **一次即止**（`once: true`），不反复触发

### 2.2 性能预算：铁律与黑名单

你说"花哨没关系，但开销别太大，雪花这种不要"——这条直接定成规则：

**铁律：只做"一次性的、合成器友好的"动效。** 一次性 = 元素进入视口时跑一次就结束；合成器友好 = 只改 `opacity` / `transform`，不触发重排。

| 等级 | 类型 | 例子 | 规则 |
|---|---|---|---|
| 免费 | 纯 CSS、静态 | 渐变文字、荧光笔、拍立得框、装饰 SVG | 随便用 |
| 便宜 | 一次性 JS + CSS 动画 | 逐字出现、点赞粒子、长按三连、罗小黑眼睛 | 用，但要 `once` 和 reduced-motion 降级 |
| **禁止** | **连续逐帧循环、逐粒子** | 雪花、雨、粒子海、Canvas 背景、WebGL 场景、循环 Lottie、视频背景 | **一律不做** |

为什么禁：前三类每一个都要在**每一帧**为几十上百个粒子算位置，主线程被持续占用，中低端手机上直接掉帧、发热、耗电——而且它们不传递任何信息，纯粹是装饰。这是"设计债"不是"设计值"。

弹幕墙是唯一的例外条款：它本质是连续动画，但**粒子数可控**（micro 一共就那么几条）、**可一键暂停**、并且只在独立彩蛋页。真机验证掉帧就退化成静态列表。

**每个动效的验收标准只有一条：关掉动效后功能完全不受影响。** 做不到就回退。

### 2.3 技术选型：三层，能不用 JS 就不用

**第一层 · 纯 CSS**（部分已在用）
滚动驱动动画（`animation-timeline: scroll()`）扩展到：卡片倾斜跟随鼠标、标签磁性吸附、文字入场。全部 `@supports` 包裹 + reduced-motion 降级。

**第二层 · View Transitions API**（跨页面）
Astro 7 内置，加一个 `<ClientRouter />` 就能让列表页卡片"飞"成详情页标题。2026 年最值钱的 API：浏览器原生、零依赖、性能由引擎保证。之前设计稿里主动放弃的页面过渡可以捡回来——但只用 fade + 卡片 morph 两种，不滑动不翻转。

**第三层 · Web Animations API**
粒子迸发、罗小黑眼睛、逐字出现这类需要按帧算的，用 WAAPI 或单个 rAF 循环，不引动画库。

**不引入**：Framer Motion / GSAP（要 React 或明显增包体）、Lottie（插画式加载，你有更好的素材）、Lenis（平滑滚动是 scroll-jacking 重灾区，且和 `scroll-behavior: smooth` 打架）。

时长表（业界共识值，直接用）：

| 类型 | 时长 |
|---|---|
| 悬停 / 聚焦 | 150–200ms |
| 按钮按下 | 100–150ms |
| 入场 | 300–500ms |
| 退场 | 200–350ms |
| 滚动触发 | 400–600ms |
| 页面过渡 | 200–300ms，**上限 300ms，超过就觉得慢** |
| 逐字出现 | 每字 25–40ms，整段不超过 1.2s |

弹性参数用 spring（damping 20 / stiffness 300 那档），不要 linear。悬停放大幅度上限：卡片 `scale(1.03)`，按钮 `scale(1.05)`，配 `translateY(-2px)`。

### 2.4 落地顺序

1. **进度条罗小黑**（一晚）：素材现成、位置现成、最容易被看见
2. **Canva 式文字四件套**（一晚）：荧光笔、渐变标题、拍立得相框、首字下沉——纯 CSS，零风险，立刻让站点"花"起来
3. **标题逐字出现**（半晚）：按词拆 + once + reduced-motion
4. **写作热力图**（一晚）：零 JS SVG，放简介页
5. **文章底部长按三连 + 点赞粒子**（一晚）：第一个"有感情"的交互
6. **View Transitions 页面过渡**（一晚）：改 `Base.astro` 一处，全局生效
7. **弹幕墙**（一晚半）：独立彩蛋页，不影响其他
8. **⌘K 命令面板**（两晚）：改造现有搜索，工作量最大收益也最大

## 三、两条线的交汇点

动效和编辑器在三件事上互相成就，要一起设计：

1. **保存成功的反馈**。`/write` 保存时给一个"罗小黑把稿子收进抽屉"的小动画 + 一句随机鼓励语——这是最该有的一个动效，因为它确认的是"我的劳动成果安全了"
2. **草稿状态的视觉化**。`draft: true` 的卡片在列表页带"未点亮"态，发布时才亮——把"发布"变成看得见的动作
3. **写作热力图同时是编辑器仪表盘**。`/write` 旁边挂张小热力图，写完一格亮一格，把"持续写"变成可累积

## 四、执行顺序与验收

| 阶段 | 内容 | 前置条件 | 验收标准 |
|---|---|---|---|
| 0 | **装 Office Viewer 扩展** | 无 | 今晚就能用工具栏写 md，git diff 正常 |
| 1 | 动效八项（2.4 顺序） | 无 | 每项关掉动效后功能无损；reduced-motion 下降级；中端手机不掉帧 |
| 2 | `/write` 本地编辑台 | 无 | 手机能打开、能发一篇带图和 frontmatter 的 md、保存后预览 3 秒内刷新 |
| 3 | 部署到固定域名 | **你选 Cloudflare / Vercel / COS** | 宿舍电脑、手机、平板同一地址 |
| 4 | Keystatic 云端编辑 | 阶段 3 | 手机浏览器打开能写能发，git 有历史 |
| 5 | 微信一句话上传 | 阶段 3 + 写够 20 篇 | 发一句话到上线不超过 3 分钟 |

阶段 0 和 1 不依赖任何决策，随时开工。阶段 3 卡在你那一票上。

## 五、风险与明确不做的事

**风险**

- Vditor 上游维护放缓，长时间不更新有可能。备选 Office Viewer Enhanced；真出事退回 VS Code 原生 + 预览分屏，损失为零
- 弹幕墙是最容易过火的一项。定成独立彩蛋页，不进首页，可一键暂停，真机掉帧就退化成静态列表
- View Transitions 在旧浏览器无感降级，但要在真机上验证手势返回是否正常
- Milkdown 的 bus factor 是真实风险，所以它是"可选升级"不是"必经之路"
- `/write` 能写文件 = 一个本地后门。只绑 `127.0.0.1`，不进生产构建，密码用环境变量，不写死在代码里

**不做**

- 不引 React / 不引动画库 / 不引平滑滚动库
- 不做任何连续粒子效果（雪花、雨、粒子海、Canvas 背景、WebGL 场景）
- 不做黑暗模式（浅色玻璃是这一版成立的前提，硬加会毁掉现在这套视觉）
- 不把内容搬离 md
- 不做块级拖拽编辑器（BlockNote 那一路）
